## 3. P0 逐條回應

### P0-1　彩色全像箔與「主視覺有箔質感」的事實錯誤

**審核意見**：主視覺上那隻貓是 100% 純黑白灰，沒有全像箔；Zero Hue Rule 只有照片例外。

**查證**：用 sharp 對原圖逐像素計算 HSL 飽和度。

```
art/QRACON2026主視覺形象圖.jpg   2268×756   飽和度 > 0.12 的像素：0（0.00%）  最高飽和度 0.000
src/assets/brand/qracon-wordmark.png        飽和度 > 0.12 的像素：0            最高飽和度 0.000
public/og-image.png                          飽和度 > 0.12 的像素：0            最高飽和度 0.000
src/assets/brand/schrodinger-cat-leaping.png 飽和度 > 0.12：378 / 739,379（0.05%）  最高 1.000（虹膜反光）
```

**判定：接受，審核者是對的。**

我在看图時把貓眼的反光讀成了箔，實際上整張主視覺的最高飽和度是 0。這是事實錯誤，不是取捨問題。

**處理**：刪除 The Foil Exception，刪除 `conic-gradient`，牌背改成「銀墨高光」（白色透明漸層掃光 + `--color-on-ink-rule` 干涉線）。整個塔羅站不新增任何色彩 token。

### P0-2　自創 token 與裸 px

**審核意見**：`--field`、`--field-raised: #0F0F0F`、`--paper` 是自創的；主站有 `--color-ink-raised: #262626`。牌面尺寸也寫了裸 px。

**判定：接受。**

**處理**：§4.1 改成全部使用主站既有 token 的對照表，零新增色彩變數。§4.4 的 `1.5px / 1px / 8px` 改成 `var(--rule-thin)`、`var(--rule-hair)`、`var(--space-2)`。

### P0-3　子路徑 `/tarot` 與文件內路由衝突

**審核意見**：`01-copy-deck.md` §7 的「重新抽一張 → `/`」、`02-plan.md` §6.4 的 `<a href="/deck/fool">` 都會跳回主站根目錄。

**判定：接受。**

**處理**：所有站內路徑改用 `import.meta.env.BASE_URL`；文案表的目標改為 `/tarot/`；§6.4 的範例改成 `/tarot/deck/[slug]`。

### P0-4　隨機抽牌與固定連結的邏輯矛盾

**審核意見**：一邊說等機率亂數選牌，一邊讓七張牌各自固定連到七個 slug，還用 `sessionStorage` 鎖住。三者互相矛盾。

**判定：接受，而且是這次審核最有價值的一條。**

我的初稿把「亂數」和「使用者選牌」混在一起了。這張牌組的設定本來就是：七張牌面朝下，你選哪一張就是哪一張。**使用者的選擇就是唯一的隨機來源**，不需要另外抽亂數。

**處理**：改成「洗位置」——頁面載入時用 Fisher–Yates 把七個 slug 洗進七個 `<a>` 的 `href`，使用者點哪個位置就開哪張牌。無 JS 時維持建置順序。「重新抽一張」＝重新載入重洗。移除 `sessionStorage` 鎖定。

### P0-5　死神圖示與自己的物理修正矛盾

**審核意見**：§7.2 寫「條紋由密到疏，最後變平」，但 B7 已經說退相干是「條紋被抹掉」，不是間距變化。

**判定：接受。**

**處理**：圖示改為「干涉條紋的明暗對比逐漸衰減，最後變成均勻灰階」。

### P0-6　結果頁仍有未證實的承諾

**審核意見**：「這張牌對應的場次在議程裡」「還有一整套冒險可以走」都是原文沒有的、也未經確認的事實。

**判定：接受。**

**處理**：改成純事實：「2026.12.13（日）中央研究院南部院區（臺南）／四個場地、一整天的量子議程，包含主題演講、工作坊、海報展示與論壇。」

### P0-7　違反 Latin-Only Sign Rule

**審核意見**：`2026.12.13（日）` 的「（日）」不能放在 `--font-sign`。

**判定：接受。**

**處理**：§4.2 補上規則，`01-copy-deck.md` §6 標註「（日）等中文字元切回 `--font-sans`」。

### P0-8　字體牌塞 13px 中文

**審核意見**：首頁牌寬最小 88px，塞 13px 的「一句定義」低於可讀下限。

**判定：接受。**

**處理**：首頁牌面只放羅馬數字、圖示、直排牌名。「一句定義」只出現在結果頁的大尺寸牌面。

### P0-9　文案違反自己訂的規則

**審核意見**：列出 7 處「不是 X，而是 Y」句型、17 處破折號、愚者牌義與坍縮矛盾、戀人科普註 61 字超過 60 字上限。

**判定：部分接受。**

「不是 X，而是 Y」分兩類：

- **糾正真實誤解的**（退相干不是波變直線、糾纏不能用來傳訊息、坍縮只是描述）：保留，但改寫句子結構。`humanizer-zh` 的規則也是「否定部分糾正真實誤解時保留」。
- **純粹抬價的**（閃電不是意外、距離不是問題、牌義是寫的不是算的）：改成直述。

愚者牌義「最後兩家都買」確實與坍縮矛盾，已改回「直到店員開口問的那一秒才決定」。
戀人科普註已縮到 70 字內，並把上限從 60 改成 70（原本的 60 是我隨手寫的，沒有依據）。
破折號全篇降到 6 處以內。

## 5. 物理修正

七項全部採納，其中三項是實質錯誤：

| 牌 | 原稿 | 修正 |
| --- | --- | --- |
| 愚者 | 「觀測前只有機率」 | 這是古典機率（只是不知道），不是疊加。改成「幾種可能同時存在，而且會互相干涉」 |
| 隱士 | 角色是觀測者，引言卻說「我不接受觀測」 | 引言改成「別隨便觀測我，但我一眼就能看穿你」 |
| 死神 | `相干 60`／`退相干 95` 並存 | 軸的設計錯誤，見下 |
| 塔 | 「狀態被丟到完全不同的地方」 | 講反了。淬火是哈密頓量瞬間改變，**狀態留在原地**，卻在新規則下變成高能激發態的疊加 |
| 糾纏 | 「量一個就知道另一個」 | 古典手套也成立。改成「共用同一個量子態，無法拆開單獨描述」 |
| 躍遷 | 只講吸收 | 補上「什麼時候跳回來、放出光子，是真正的量子隨機」（自發輻射） |
| 太陽 | 「相干光」與「同調光」兩種譯名並存 | 統一成「相干光（同調光）」 |

### 屬性四軸的根因

審核指出死神「相干 60／退相干 95」矛盾。這不是數值填錯，是**軸的設計錯**：相干與退相干是同一件事的兩面，兩軸並列必然出現矛盾。

**處理**：第四軸由「退相干」改為「能階」。四軸變成疊加、糾纏、相干、能階，互相獨立。七張牌的數值全部重填。

## 6. 我保留的一項判斷：死神的中心性

審核建議把死神在契合度表的出現次數降下來。我保留，理由：

1. **物理上就是如此。** 退相干是每個量子系統最後都會遇到的事——它就是量子世界裡那個「大家都會碰到」的角色。
2. **關係圖是單向的**，文案已經明說「你的夥伴是 X 不代表 X 的夥伴是你」，不會誤導。
3. 拿掉死神的中心性，換來的是關係圖更平均，但敘事更弱。

只在 §5 加一行編輯註說明這是刻意的，不對使用者顯示。
